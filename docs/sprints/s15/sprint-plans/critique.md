## Concerns
- **C-001 [major] — `eframe 0.37` silently flips the default renderer from `glow` (OpenGL/WebGL2) to `wgpu` (`wgpu 30.0`) and adds `system_fonts`, with a `wayland-sys` CI coupling trap if `default-features = false` is chosen:** `eframe 0.29.1` defaulted to `glow`, whereas `eframe 0.37.0` drops `glow` from `default` and enables `wgpu` (`egui-wgpu` + `wgpu 30.0` + `wgpu-core`/`wgpu-hal`/`naga`/`ash`) plus `system_fonts` (`egui_system_font_provider` + `fontique`), `clipboard`, and `links`. Neither `research-report.md` nor `T-003` acknowledges this backend switch (which substantially enlarges compile time, dependency count, and wasm bundle size and changes runtime WebGPU/WebGL2 initialization). In addition, `rfd 0.18`'s default `wayland` feature enables `wayland-backend/client_system` (`wayland-sys/client`), which probes `pkg-config wayland-client` (`libwayland-dev` is absent from `.github/workflows/ci.yml:89`) unless `wayland-backend/dlopen` is unified via `winit/default`. **Fix:** In `build-plan.md` `T-003`, explicitly decide and record the `eframe 0.37` feature set: either (a) intentionally adopt `eframe 0.37` defaults (`wgpu` + `system_fonts`, noting `egui-wgpu/default` retains `wgpu/webgl` fallback and `fontique/fontconfig-dlopen` + `winit/default` keep Ubuntu CI apt deps unchanged), or (b) stay on `glow` via `default-features = false, features = ["accesskit", "default_fonts", "glow", "wayland", "web_screen_reader", "winit/default", "x11"]` — explicitly retaining `"winit/default"` so `wayland-backend/dlopen` remains unified for `rfd 0.18` on Ubuntu CI.
- **C-002 [major] — `T-003` understates `egui`/`eframe 0.37` structural breaking changes and omits `-D warnings` enforcement on `wasm32` codepaths:** Inspecting `eframe-0.37.0/src/epi.rs` and `egui-0.37.0/src/containers/panel.rs` confirms that `eframe::App::update(&mut self, ctx, frame)` is removed in favor of `eframe::App::ui(&mut self, ui: &mut egui::Ui, frame)`, `egui::TopBottomPanel` is removed in favor of `egui::Panel::top`/`bottom`, and both `Panel::show` and `CentralPanel::show` now take `ui: &mut Ui` instead of `&Context` (touching 5 panel sites in `apps/carbide-ui/src/app/mod.rs:321,331,416,559,644` while `Window::show`/`Area::show` continue taking `ui.ctx()`). In addition, `egui::Margin::symmetric` (`ribbon.rs:159`) now takes `i8` instead of `f32`, and `painter.rect_filled`/`rect_stroke` (`render_square.rs`, `render_voronoi.rs`) take `CornerRadius` (plus `StrokeKind`). - **C-003 [major] — `T-004` MSRV computation (`verify_msrv_alignment`) has unsupported-platform inflation, `edition = "2024"`, and semver-normalization edge cases:** Running `cargo metadata --locked --manifest-path apps/carbide-ui/Cargo.toml --format-version 1` without `--filter-platform` includes dependencies for targets Carbide never builds (e.g., `wasip3`, `wasip2`, `wit-bindgen`, and `android`/`ios` crates), which can falsely inflate `rust-version` above Carbide's supported targets.
