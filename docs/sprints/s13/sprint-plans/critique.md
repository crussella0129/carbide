# Sprint 13 Plan Critique

## Concerns
- **C-001 — Missing Rust visibility & re-export specifications in `build-plan.md` (`T-001`..`T-004`) risk compile and `-D warnings` failures:**
  - **Child-module types and helpers (`T-001`):** `types.rs` (13 structs/enums, plus struct fields on `EditState`, `FillDrag`, `CondDraft`, `CellEdit`, `FormatEdit`, `HexFormatEdit` and inherent methods on `CondKind`/`CondDraft`), `helpers.rs` (29 fns), and `voronoi_helpers.rs` (14 fns/consts) are currently private in `app.rs`. Moving them verbatim without changing their visibility to `pub(super)` will fail `use types::*; use helpers::*; use voronoi_helpers::*;` in `mod.rs` (`E0603`).
  - **Cross-module `impl CarbideApp` methods (`T-002`..`T-004`):** `research-report.md` §5 correctly notes that child modules can access private `CarbideApp` fields, but omits that inherent `impl CarbideApp` methods defined inside a child module default to private *to that child module*, not `mod app`. Across the extracted `impl` modules, 70 methods are called across module boundaries (e.g., `draw_grid`, `draw_hex_grid`, `draw_triangle_grid`, `draw_voronoi_grid`, `mark_dirty`, `maybe_autosave`, `handle_save`, `handle_open`, `drain_pending_open`, `rebind_sheet_ids`, `cell_text`, `apply`, `begin_edit`, `commit_edit`, etc.) and must be marked `pub(super)`, while the ~25 single-module-only helpers (e.g., `paint_hex`, `apply_square_border`) stay private.
  - **`pub(crate)` preservation (`T-003`):** `CarbideApp::capture_state` (`app.rs:5419`) and `CarbideApp::restore_state` (`app.rs:5481`) are `pub(crate)` and move to `io.rs`; `T-003` and `verify_public_api_unchanged` should explicitly require preserving their `pub(crate)` visibility (neither widened to `pub` nor narrowed to `pub(super)`).
  - **Glob re-export vs. explicit-import conflict (`T-001` vs. `T-004`):** After `T-004`, `mod.rs` itself references **zero** items from `voronoi_helpers.rs` directly (all callers live in `render_voronoi.rs`, `dialogs.rs`, `cells.rs`, `io.rs`, `edit.rs`, and `tests.rs`). If sibling modules follow `T-002` Notes / `research-report.md` ("keep imports minimal and explicit") by importing from `super::voronoi_helpers::...` directly instead of `super::...`, then `use voronoi_helpers::*;` in `mod.rs` will fail `cargo clippy --all-targets -- -D warnings` and `cargo build --target wasm32-unknown-unknown` with `unused_imports` (since `#[cfg(test)] mod tests;` is excluded from lib/bin/wasm32 targets). Clarify one consistent rule: either sibling modules import via `super::{...}` (keeping `mod.rs`'s private `use` prelude live in non-test builds and leaving `tests.rs`'s `use super::*;` untouched), or drop glob imports in `mod.rs` once callers move out and import explicitly in sibling modules + `tests.rs`.
- **C-002 — `test-plan.md` Intent Traceability table omits `verify_workspace_regression` and `T-004`'s workspace EARS clause:**
  - `build-plan.md` `T-004` includes an explicit EARS clause requiring `cargo test --workspace` on the root workspace to pass with 639/639 total tests (308 UI + 331 workspace).
  - `test-plan.md` defines `verify_workspace_regression` under `## Integration Tests` (and `verify_github_actions_ci_on_dev` under `## End-to-End Tests`), but neither appears in the `## Intent Traceability` table, leaving `T-004`'s workspace-regression EARS clause untraced in the traceability matrix. Add `verify_workspace_regression` (and `verify_github_actions_ci_on_dev`) to the AC-2/AC-3 rows in `## Intent Traceability`.
- **C-003 — Minor verification loopholes in `test-plan.md` (`verify_ui_fmt_clippy_no_allows`):**
  - `git grep -n "#\[allow(" apps/carbide-ui/src/app/` misses inner attributes (`#![allow(...)]`) and whitespace variants, and silently skips untracked newly created files if executed before `git add`. Tighten to `git grep --untracked -nE "#!?\[[[:space:]]*allow\(" apps/carbide-ui/src/app/` (or run after staging/committing) so no `#![allow(...)]` suppression can slip through.
