## Concerns
- **C-001 [major] — Cross-sheet Voronoi cut-and-paste breaks single-step undo atomicity and creates cross-lattice asymmetry (`T-003`, `apps/carbide-ui/src/app/edit.rs`):** `T-003` Notes specifies clearing Voronoi cut origins when pasting onto another sheet, but `apply_edits(&mut self, sheet: SheetId, ...)` (`edit.rs:57`) only accepts one `SheetId`. Calling `apply_edits` twice (once to clear Voronoi origins, once to write destination cells) records two separate `Action::Cells` undo entries so a single Undo leaves the cut cells deleted; meanwhile Square/Hex/Triangle cuts only clear origins on the same sheet (`edit.rs:263, 294, 321`). **Fix:** Add `apply_multi_sheet_edits(&mut self, targets: Vec<(SheetId, String, Option<String>)>)` (deduplicating by `(SheetId, addr)` and recording a single `Action::Cells(Vec<CellEdit>)`, which already carries `sheet: SheetId` per edit) and extract a shared `cut_clear_targets(&self)` helper so same-sheet and cross-sheet cut/paste execute atomically in one undo step across all four lattices.
- **C-002 [major] — `Clipboard` dual cut state, Escape (`ClearMarquee`) check, and Voronoi post-paste selection/orientation are underspecified (`T-003`, `clipboard.rs`, `commands.rs`, `edit.rs`):** `Command::ClearMarquee` (`commands.rs:143`) checks `self.clipboard.cut_origin().is_some()`, which will miss a separate `cut_voronoi` field and break Escape-to-cancel on Voronoi cuts; two independent `Option` cut fields also allow an inconsistent dual-cut state. In addition, `T-003` does not specify whether Voronoi's `1 × N` block is `(width=1, height=N)` or `(width=N, height=1)`, nor how `self.voronoi.selection` updates after pasting onto Voronoi (leaving stale `selection.extra` highlights if not reset). **Fix:** Store cut state in `Clipboard` as a single `Option<CutOrigin>` (`Grid(i32, i32)` | `Voronoi(Vec<VoronoiCoord>)`), add `has_cut()`/`cut_voronoi_cells()`, clear `cut` in `consume_cut()`, switch `commands.rs:143` to `self.clipboard.has_cut()`, standardize Voronoi copy as `width = 1, height = cells.len() as u32` (newline-separated TSV), and update `self.voronoi.selection` after a Voronoi paste to `collapse_to(cursor)` plus `extra.extend(pasted_coords.into_iter().skip(1))`.
- **C-003 [major] — Voronoi `italic` text rendering cannot use `painter.text(...)`, and note marker dots must not be skipped on empty/widget cells (`T-001`, `T-002`, `render_voronoi.rs`):** `T-001` EARS requires `draw_voronoi_grid` to render `italic`, `bold`, `font_size`, `underline`, and `strikethrough`. Unlike `draw_cell_text` (`helpers.rs:48-75`), `paint_hex` (`render_hex.rs:77-83`) uses `painter.text(...)` with `FontId`, which does not support italics in egui — mirroring `paint_hex` would silently miss `italic`. In `render_voronoi.rs:173-191`, the text loop also `continue`s early for widget cells and empty text, which would hide note dots on empty or widget cells if drawn inside that loop. **Fix:** Render Voronoi centroid text with `egui::text::LayoutJob` + `painter.layout_job` + `painter.galley` (centered on centroid, with faux-bold offset and `draw_text_decorations`), and draw `voronoi_notes.has(coord)` marker dots outside the widget/empty-text early-`continue` guards (matching `render_hex.rs:86-90`).
- **C-004 [minor] — Legacy v2 `UiSnapshot` compatibility test can be masked by `ui_state_to_snapshot`'s `.unwrap_or_default()` (`T-001`, `T-002`, `state_io.rs`, `test-plan.md`):** `ui_state_to_snapshot` (`state_io.rs:119-121`) falls back to `UiSnapshot::default()` on any deserialization error, so asserting empty `voronoi_formats`/`voronoi_notes` through `ui_state_to_snapshot` alone would pass even if serde failed. **Fix:** Decode the legacy v2 fixture directly with `serde_json::from_value::<UiSnapshot>(legacy_json).unwrap()` (matching `v145_snapshot_loads_square_widgets_via_alias` at `state_io.rs:272`) and assert non-default legacy fields (`active_sheet`, `stage_mode`, `square_notes`) survive alongside empty Voronoi maps.
- **C-005 [minor] — Plan/code hygiene mismatches (`T-001`–`T-004`, `test-plan.md`, `mod.rs`, `edit.rs`, `commands.rs`):** (1) `test-plan.md:7` references `verify_widget_toggle_helper` in the traceability table, which is undefined in the body (covered under `verify_unified_format_and_widget_helpers` at line 16). (2) `T-002` lists `apps/carbide-ui/src/app/render_triangle.rs` in `Touches` even though it has no context menu or note-open code and no `T-002` requirement targets it. (3) In `mod.rs:480-484`, keeping `!self.voronoi.selection.extra.is_empty()` while switching the count to `selection.cells().len()` will display `"1 cells"` when a marquee selects only the active cursor cell; guard on `let n = self.voronoi.selection.cells().len(); if n > 1`. (4) `commit_edit` (`edit.rs:83-86`) omits clearing `triangle`/`voronoi` `formula_highlight`/`formula_drag` and `Command::Cancel` (`commands.rs:128-133`) omits clearing `voronoi`'s; add a shared `clear_formula_refs(&mut self)` helper (AC-3). (5) Match `WidgetKind` by `std::mem::discriminant` in `toggle_widget_kind` so it remains safe for parameterized variants (`Slider`/`ProgressBar`). **Fix:** Update `test-plan.md:7` and `T-002`'s touch list, guard the Voronoi selection badge on `n > 1`, add `clear_formula_refs` in `T-003`, and use discriminant matching in `toggle_widget_kind` in `T-004`.
